# 10 · Shipping an MLO to a buyer

**Rule (Antonio, 2026-10-24): every MLO we ship includes a conflict checker and instructions for using it.** No exceptions,
however small the map. It ships inside the resource and is generated by the build, never hand-kept.

## What every package contains
1. **The resource(s)**, built by the project's assemble step from source (never hand-edited outputs).
2. **`<resource>/README.md`** for the buyer. Start from `tools/shipping/README_TEMPLATE.md`; the full example is
   `tools/towercity/buyer_README_example.md`. It must cover:
   - install order (`ensure` after its dependencies) and that a map needs a **full server restart**
   - **"Check for conflicts first"**: how to run the conflict checker, what it reports, and what to do about each line
     (section below; copy it word for word and fill in the names)
   - every config switch with its shipped default
   - access / lock lists, with full identifier examples (`license:...`, `discord:...`, `fivem:...`), where to copy them from
     (txAdmin, Players, the player, IDs), and the empty-list trap (a check switched on with an empty list locks everyone out)
   - render targets, if any: model, target name, texture name, how to hook another TV / DUI script in, the busy flag, and the
     one-target-per-model limit
   - water (only one water map is active), IPL loaders and what we keep off, and integrations offered separately
     (e.g. rcore_casino)
   - which Rockstar files the map replaces, and a troubleshooting table
3. **`<resource>/tools/check_conflicts.ps1`**, written by `tools/shipping/make_conflict_check.py` in the assemble step.
4. **`mlo-data/`** (JSON + README): doors, seats, spots, zones, lifts, TVs (see 08).

## The conflict checker
- `make_conflict_check.py` lists every file in `stream/` that is not ours (our prefix, default `tc_`), plus `_manifest.ymf`
  excluded: those are the Rockstar files we replace, and any other resource replacing the same name fights ours (only one loads).
- `--family` also flags same-area Rockstar families under other names (e.g. `^(hei_|hi@|ma@)?(dt1_11|dt1_12)`), and `--refs`
  flags scripts that load IPLs / interiors there (e.g. `bob74_ipl` turning on the Maze Bank offices).
- Our own folders are skipped (`--res`, `--skip`), so the buyer can run it before **or** after installing.
- Run it in the assemble step after the stream folder is final. Tower City example: `TowerCity/work/assemble.sh`.
- **Prove it before shipping**: a scratch `resources` folder with a fake resource holding one listed file, one same-family file,
  and a script naming one `--refs` entry, plus a copy of our own resource. All three must be reported, and ours must not be.
- Also say in the README what it can't see: another MLO at the same spot under different file names. Give the street names and
  x / y so the buyer can check by hand.

## README section to include (fill in the names)
```markdown
## Check for conflicts first
Before (or after) installing, run this from your server's `resources` folder:

    powershell -ExecutionPolicy Bypass -File .\<resource>\tools\check_conflicts.ps1

It reads files only and changes nothing. It reports:
- **SAME FILE**: another resource ships a Rockstar file this map also replaces. Only one copy loads, so you get holes, missing
  roads or old buildings showing through. Remove that file from the other resource (or the other resource), or keep theirs and
  not this map.
- **same area**: another resource replaces a different Rockstar file in the same block. Usually fine, but check that area in game.
- **scripts that use the area**: a script loads an interior / IPL here (e.g. an IPL loader). Note what this map already turns off
  for you (see below), and check the rest.

It can't see another MLO placed at the same spot under different file names. Check around <streets>, x <x> y <y> by hand.
```

## Shipping defaults
Optional moving parts are off (escalators), every access check is off (all floors open), and the owner turns on what they want.
